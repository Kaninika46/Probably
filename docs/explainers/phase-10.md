# Phase 10 explained: FastAPI read-only backend and React + TypeScript web interface

## What we did, in plain words

**1. Replace the Streamlit prototype with a read-only FastAPI backend (`api/main.py`, `api/schemas.py`).**
Instead of mixing UI code and database queries in a single Streamlit script, we built a clean HTTP boundary in `api/main.py` backed by typed Pydantic v2 models in `api/schemas.py`. Every endpoint opens `app/app.duckdb` (`1,847,296` bytes, 3,961 S3 customers) via `get_readonly_connection()` with `duckdb.connect(str(APP_DB_PATH), read_only=True)` or reads pre-computed tables from `reports/tables/`:
- `GET /api/health` — confirms the API is running and `app/app.duckdb` is reachable in read-only mode.
- `GET /api/meta` — returns the three headline revenue figures (`£19,287,250.57` raw net revenue across `1,067,371` rows, `£19,643,861.64` clean product sales revenue across `1,003,357` rows, `£7,004,392.65` S3 9-month customer revenue across `3,961` customers), the five Okabe–Ito colour-blind-safe segment descriptors, the IPCC AR5 / Sherman Kent hedge lexicon (`almost certainly` $\ge 0.90$, `very likely` $\ge 0.80$, `probably`/`likely` $\ge 0.66$, `about as likely as not` $\in [0.40, 0.60]$, `unlikely` $\le 0.33$, `borderline` $< 0.65$), available countries (`38` countries in S3), the six question templates (`Q1`–`Q6`), six example questions, and the default method (`gmm`, marked **PROVISIONAL**).
- `POST /api/ask` — calls `src.nl.engine.answer_question(question, method=..., threshold_override=..., boundary_override=..., conn=conn)` directly. It never generates free-form SQL and never evaluates user strings in the database; it returns the parsed slots, the human-readable interpretation sentence, the parameterised SQL template, the bound parameters, summary metrics (`matched_count`, `expected_count`, `hard_count`, `expected_revenue_gbp`), and up to 500 result rows.
- `GET /api/segments?method=gmm|bootstrap` — queries `segments`, `customer_segment_membership`, and `customers` in `app/app.duckdb` plus `sql/templates/q3_expected_size.sql` and `sql/templates/q4_expected_revenue.sql` to return original-unit medians, hard vs expected counts ($\sum_i p_{ik}$ vs K-Means hard count), expected revenue ($\sum_i p_{ik} m_i$), the surrogate depth-4 decision-tree rule (with 86.80% test fidelity), and a 10-bin histogram of $\max_k p_{ik}$.
- `GET /api/segments/map?method=gmm|bootstrap` — returns all `3,961` S3 customers with their RFM features (`recency_days`, `frequency`, `monetary`, `country`), top-2 segment probabilities (`p_1`, `p_2`, `margin = p_1 - p_2`), Shannon entropy $H(p_i) = -\sum_k p_{ik}\ln p_{ik}$, and 90-day lapse probability `p_lapse`.
- `GET /api/customers/{customer_id}?method=gmm|bootstrap` — returns a single customer's full 5-segment probability vector, lapse probability, RFM profile, matched surrogate tree rule, and recent clean invoice summary from `data/processed/transactions_clean.parquet`.
- `GET /api/lapse?method=gmm|bootstrap&tau_seg=0.66&tau_lapse=0.66&country=` — returns the S2 temporal evaluation metrics for the L2-regularised logistic regression model (`Brier = 0.1684`, `Brier skill score = +0.1672` / `+16.72%` vs base rate, `ROC-AUC = 0.7852`, `ECE = 0.0252`) alongside the three comparator models (`tree_depth4_calibrated`, `two_bin_recency_90d`, `base_rate`), the 10-bin reliability diagram on S2, the feature coefficients, and the live S3 high-value at-risk cohort table via `Q6`.
- `GET /api/quality` — returns the 6-step cleaning funnel (`1,067,371` raw rows down to `776,596` customer-assigned clean rows), the 40-row GMM BIC/AIC grid across $K \in \{2,\dots,10\}$ and all four covariance types, the 100 bootstrap ARI sample values (`mean = 0.8588`, `median = 0.9467`, `std = 0.1456`), per-segment bootstrap Jaccard stability (`Champions = 0.940`, `Loyal = 0.888`, `At-Risk = 0.863`, `New = 0.831`, `Hibernating = 0.822`), the go/no-go gate report, and the NL dev evaluation (`32/32 = 100%` template, parameter and result-set accuracy on dev; test set honestly reported as pending external questions).

**2. Build the React + TypeScript + Tailwind web application (`web/`).**
We built a six-page single-page application in `web/src/` designed around the principle **"colour only means data"**:
- Neutral slate chrome (`--bg`, `--surface`, `--ink`, `--line`) in both light mode (default) and dark mode, with CSS custom properties defined exclusively in `web/src/styles/tokens.css`.
- Okabe–Ito colour-blind-safe categorical palette for the five segments (`Champions` `#009E73`, `Loyal` `#0072B2`, `New` `#CC79A7`, `At-Risk` `#E69F00`, `Hibernating` `#7A7F87`) and a separate 4-step sequential red ramp for 90-day lapse risk (`--lapse-1` to `--lapse-4`).
- Self-hosted fonts (`@fontsource/source-serif-4`, `@fontsource/inter`, `@fontsource/jetbrains-mono`) so the app renders identically offline with tabular numerals (`font-variant-numeric: tabular-nums`) on every numeric column and tile.
- Five custom components (`ProbabilityBar`, `ParseStrip`, `ThresholdControl`, `UncertaintyMap` HTML5 Canvas scatter plot of all 3,961 customers, and `CustomerDrawer`) across six pages (`Overview`, `Ask`, `Segments`, `Lapse risk`, `Model quality`, and `About`).
- When built with `npm run build` (`tsc -b && vite build`), `api/main.py` serves `web/dist` directly on `http://localhost:8000` so the entire application runs from a single command (`run_app.bat`).

## Likely viva questions

**1. How does the browser talk to the Python pipeline when a user asks a question on `/ask`?**
When the user submits a question or clicks an example chip in `AskPage.tsx` (or drags the threshold slider in `ThresholdControl.tsx` after a 150ms debounce), `web/src/lib/api.ts` sends an HTTP `POST /api/ask` request with JSON body `{"question": ..., "method": "gmm" | "bootstrap", "threshold_override": ..., "boundary_override": ...}`. FastAPI validates the request with `AskRequest` (`api/schemas.py`), opens a read-only connection to `app/app.duckdb`, and calls `src.nl.engine.answer_question()`. Python runs the spaCy + regex slot parser (`src/nl/parser.py`) and executes the matching parameterised SQL template (`sql/templates/q1..q6.sql`) via `src/prob_queries.py`. FastAPI serialises the result as `AskResponse` JSON, and React renders the interpretation sentence, `ParseStrip`, `ThresholdControl`, summary tiles, `ProbabilityBar` rows, and SQL drawer.

**2. Why is all analytical logic kept in Python (`src/`) instead of computing expected counts or parsing thresholds in TypeScript?**
Keeping all analytical and query logic in `src/` enforces a single source of truth between the offline evaluation suite (`pytest` and `reports/tables/`) and the interactive web application. If the React frontend re-implemented hedge parsing, threshold filtering, or expected value summation ($\sum_i p_{ik} m_i$) in TypeScript, the UI could silently drift from the tested Python implementation. Instead, the browser only renders values returned by `/api/*` and sends user adjustments (`method`, `threshold_override`, `boundary_override`, `tau_seg`, `tau_lapse`) back to the API.

**3. How do you guarantee that the web API is read-only and immune to SQL injection?**
We enforce three independent safeguards tested in `tests/test_api.py`:
1. **Input refusal & slot parsing (`src/nl/parser.py`):** Any input containing SQL tokens (`;`, `--`, `/*`, `DROP`, `UNION SELECT`, `1=1`) is immediately classified as `OUT_OF_SCOPE` before any database call occurs (`test_ask_endpoint_handles_probably_almost_certainly_out_of_scope_and_injection`).
2. **Closed template catalogue & allow-listed parameter binding (`src/prob_queries.py`):** Only the six static SQL files (`sql/templates/q1_probably_in_segment.sql` through `q6_segment_and_lapse.sql`) can ever be executed, and every parameter (`$segment`, `$tau`, `$country`, `$method`) is validated against strict Python allow-lists and bound as a DuckDB query parameter (`con.execute(sql, params)`), never interpolated into the SQL string.
3. **Storage-engine read-only mode (`api/main.py`):** `get_readonly_connection()` calls `duckdb.connect(str(APP_DB_PATH), read_only=True)`. Even if code attempted `CREATE`, `INSERT`, or `DROP`, DuckDB rejects it with `duckdb.InvalidInputException: Cannot execute statement of type "CREATE" on database "app" which is attached in read-only mode!` (`test_database_connection_refuses_writes`).

**4. Why does the Uncertainty Map on `/segments` use an HTML5 `<canvas>` element instead of an SVG chart library?**
Snapshot S3 contains `3,961` active customers, each drawn with an outer uncertainty halo (scaled by $1 - p_{i,1}$ when $\max_k p_{ik} < 0.65$) plus an inner solid circle coloured by its top segment. Rendering `7,922` DOM nodes in SVG slows down layout, hover hit-testing, and panning/filtering. Using an HTML5 `<canvas>` scaled by `window.devicePixelRatio` draws all `3,961` points in a single frame (<5 ms) while supporting crisp Retina rendering, spatial quad/distance hit-testing on hover, and instant click-to-open for the customer slide-over drawer.

**5. Why are both `gmm` and `bootstrap` exposed as a persistent toggle in the top bar, and why is `gmm` marked PROVISIONAL?**
Both membership estimators live side-by-side in `app/app.duckdb` (`customer_segment_membership` keyed by `(customer_id, snapshot_id, segment_id, method)`). While bootstrap co-assignment ($B = 100$, mean ARI $= 0.8588$, all 5 segment Jaccards $\ge 0.822 > 0.75$) verifies that the 5-cluster structure is genuinely stable under resampling, its empirical frequencies are concentrated near $\{0, 1\}$ (only `1.44%` of customers have $\max_k p_{ik} < 0.80$). By contrast, spherical GMM ($K = 5$) produces smoother posterior probabilities across cluster boundaries (`5.86%` with $\max_k p_{ik} < 0.80$, `250` customers with $\max_k p_{ik} < 0.65$), making boundary uncertainty visible when demonstrating `Q1`, `Q2`, and `Q6`. Because `5.86%` is below the original `10%` softness target in `CLAUDE.md` Section 7.5, both the $K = 5$ spherical selection and `DEFAULT_METHOD = 'gmm'` are explicitly marked **PROVISIONAL** in `docs/DECISIONS.md` and in the UI.
